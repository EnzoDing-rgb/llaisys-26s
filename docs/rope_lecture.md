# 任务 2.5：旋转位置编码（RoPE）讲义

> 写给还不知道 RoPE 是什么的同学。目标有两层：先建立「为什么需要它」的直觉，再把 README 与本仓库测试里**真正要算的公式**讲清楚，最后落到你实现时该怎么扫内存。

---

## 1. 先问一个朴素问题：注意力怎么知道「谁在前、谁在后」？

自注意力的核心是：每个位置的查询向量 $q$ 去和各个位置的键向量 $k$ 做内积，内积大就更关注那里。

假设序列只有两个词，内容向量碰巧算出来一模一样：

```text
位置 0：「猫」→ q0 = k0 = (1, 0)
位置 1：「狗」→ q1 = k1 = (1, 0)
```

若不做任何位置处理，那么：

- `q0 · k0` 与 `q0 · k1` 完全一样；
- 模型分不清「猫在狗前面」还是「狗在猫前面」。

语言里词序往往改变意义（「猫咬狗」vs「狗咬猫」）。因此 Transformer 必须把**位置信息**注进表示里。早期常见做法是给词向量**加上**一份位置向量（绝对位置编码）。RoPE 走另一条路：它不往向量上「加一个位置偏置」，而是对 $q$ / $k$ **做旋转变换**，让内积自然带上相对位置信息。

一句话直觉：

> RoPE 把「第几个 token」编码成「在某些二维平面上转了多大角度」；两个位置差得越远，它们对应的旋转差得越多，内积随之改变。

---

## 2. 用二维旋转把「位置」变成「角度」

先把问题缩到最小：一个长度为 2 的向量 $(x_0, x_1)$，以及一个角度 $\phi$。平面旋转是：

$$
x_0' = x_0 \cos\phi - x_1 \sin\phi
$$

$$
x_1' = x_0 \sin\phi + x_1 \cos\phi
$$

（你也可以把 $(x_0, x_1)$ 看成复数 $x_0 + i x_1$，乘上 $e^{i\phi}$。）

**关键性质（相对位置）：**

若位置 $m$ 的向量转 $\phi_m$，位置 $n$ 的向量转 $\phi_n$，则它们内积只依赖于旋转差 $\phi_m - \phi_n$。当角度按位置线性增长（例如 $\phi_p = p \cdot \omega$）时，内积就主要反映**相对距离** $m - n$，而不是某个绝对坐标本身。这正是「位置编码」想要的：模型关心的是「你在我前面第几位」，而不是「全球编号是不是 10000」。

RoPE 做的事，本质上就是：把高维的 $q$ / $k$ **拆成许多个二维小组**，每一组用**自己的频率**转一个与位置 $p$ 成正比的角。

---

## 3. 本作业采用的拆分方式（务必对照 README，不要凭印象）

文献里 RoPE 有两种常见「两两配对」方式：

1. **交错配对**：$(x_0, x_1)$、$(x_2, x_3)$、…
2. **前后对半**：前一半当 $a$，后一半当 $b$，再按下标 $j$ 一一配对。

**本仓库 README 与 `test/ops/rope.py` 用的是第 2 种。**

设某个 head 上、某个 token 的向量长度为 $d$（必须是偶数），写作：

$$
x = [a,\ b] \in \mathbb{R}^{d}
$$

$$
a,\ b \in \mathbb{R}^{d/2}
$$

也就是：

```text
下标:   0 1 2 ... d/2-1 | d/2  d/2+1 ... d-1
含义:   <---- a 前半 ----> <------ b 后半 ------>
```

对每个 $j = 0, 1, \dots, d/2 - 1$，把 $(a_j, b_j)$ 当成一个二维点来旋转，得到 $(a'_j, b'_j)$。  
整段输出仍是 $[a',\ b']$，形状与输入相同。

### 小例子（$d = 4$）

输入一个向量：

```text
x = [x0, x1, x2, x3]
      \___a___/ \___b___/
a = [x0, x1]
b = [x2, x3]
```

有两个配对：

- $j = 0$：旋转 $(a_0, b_0) = (x0, x2)$
- $j = 1$：旋转 $(a_1, b_1) = (x1, x3)$

**不是**旋转 $(x0, x1)$ 与 $(x2, x3)$。实现时如果配对方式写错，数值会对不上测试。

## 4. 角度怎么定：$\phi_{i,j}$ 与 $\theta$

对序列里第 $i$ 个输入位置（$i = 0, \dots, \mathrm{seqlen}-1$）：

- $p_i$：该 token 的**位置 id**（来自 `pos_ids[i]`，类型 int64）
- $d$：head 维度
- $\theta$：频率基数，测试里固定为 `10000.0`
- $j = 0, 1, \dots, d/2 - 1$

README 给出：

$$
\phi_{i,j} = \frac{p_i}{\theta^{2j/d}}
$$

测试参考实现写成等价形式：

```text
freqs[i, j] = pos_ids[i] / (theta ** (2 * j / d))
```

然后 `sin = sin(freqs)`，`cos = cos(freqs)`。

### 为什么 $j$ 越大，转得越慢？

指数 $2j/d$ 随 $j$ 增大而增大，分母 $\theta^{2j/d}$ 变大，于是同一位置 $p_i$ 对应的 $\phi_{i,j}$ 变小。

直观图像：

- $j = 0$：频率最高，位置稍变，角度变很多（刻画细粒度的相对位置）
- $j$ 接近 $d/2 - 1$：频率很低，角度几乎随位置缓慢变化（刻画更长程的相对关系）

这和经典 Transformer 里「不同维度用不同波长的正弦」是同一类思想，只是这里用旋转来注入。

### 用数字走一遍（$d = 4$，$\theta = 10000$，$p = 2$）

当 $j = 0$：

$$
\phi = \frac{2}{10000^{0}} = \frac{2}{1} = 2
$$

当 $j = 1$：

$$
\phi = \frac{2}{10000^{2/4}} = \frac{2}{10000^{0.5}} = \frac{2}{100} = 0.02
$$

同一 token、不同配对，转角可以差两个数量级——这是预期行为。

## 5. 最终要算的公式（实现时的「真理」）

对每个序列下标 $i$、每个 head、每个配对 $j$：

$$
a'_{i,j} = a_{i,j}\cos\phi_{i,j} - b_{i,j}\sin\phi_{i,j}
$$

$$
b'_{i,j} = b_{i,j}\cos\phi_{i,j} + a_{i,j}\sin\phi_{i,j}
$$

注意第二式是 $b\cos\phi + a\sin\phi$（不是把第一式里 $a$/$b$ 简单对调），对应标准二维旋转。

写回向量时：

```text
out[..., 0 : d/2]     = a'
out[..., d/2 : d]     = b'
```

## 6. 张量长什么样：把 README 参数落到本仓库

函数签名：

```c++
void rope(tensor_t out, tensor_t in, tensor_t pos_ids, float theta);
```

| 参数 | 含义 | 形状 / 类型 |
|------|------|-------------|
| `in` | 原始的 **Q 或 K**（RoPE 通常只旋 Q/K，不旋 V） | `[seqlen, nhead, d]` 或 `[seqlen, nkvhead, d]`，连续 |
| `out` | 旋转后的 Q 或 K | 与 `in` 相同 |
| `pos_ids` | 每个 token 在**整段上下文**中的位置编号 | `[seqlen]`，`int64` |
| `theta` | 频率基数 | 标量 `float`，测试用 `10000` |

作业约定：你可以暂时假设 `in` / `out` 连续；dtype 至少支持 **F32 / F16 / BF16**（半精度建议在 float 里算三角与乘加，再 cast 回去）。

### 测试用例在说什么

`test/ops/rope.py` 里有两组：

1. `shape=(2, 1, 4)`，`pos_ids` 为 `0, 1`
   - 序列长度 2，1 个 head，头维 4
   - 适合手算核对

2. `shape=(512, 4, 4096)`，`pos_ids` 为 `512, 513, ..., 1023`
   - 序列长度仍是 512，但位置编号**从 512 起**，不是从 0 起

第二组非常重要：它模拟「前面已经有一段上下文（例如 KV cache 里已有 512 个 token），当前这段新 token 的绝对位置从 512 继续编号」。

因此实现时角度必须用 **`pos_ids[i]`**，不能偷懒写成循环下标 `i`。若你写成

$$
\phi = \frac{i}{\theta^{2j/d}}
$$

而不是用 $p_i$，第一组偶然能过，第二组会挂。

## 7. 建议的实现扫描顺序（与测试参考一致）

对连续布局 `[seqlen, nhead, d]`，可以按下面理解（伪代码）：

```text
half = d / 2
for s in 0 .. seqlen-1:                  # 每个 token
    p = pos_ids[s]                        # 绝对位置，可能从 512 起
    for h in 0 .. nhead-1:                # 每个 head（彼此独立做同样旋转）
        取出该 head 的向量 x[0..d)
        a = x[0 .. half)
        b = x[half .. d)
        for j in 0 .. half-1:
            phi = p / theta**(2*j/d)
            a'[j] = a[j]*cos(phi) - b[j]*sin(phi)
            b'[j] = b[j]*cos(phi) + a[j]*sin(phi)
        写回 out 对应位置
```

工程上仍建议沿用本仓库算子分层：

- `op.cpp`：校验设备、形状、dtype、连续性；从 Tensor 拆出指针与 `seqlen` / `nhead` / `d`
- `cpu/rope_cpu.cpp`：真正按上面公式计算；F16/BF16 用 `utils::cast` 走 float

## 8. 和前后算子的关系（建立整条流水线直觉）

在典型 LLaMA 风格块里，顺序大致是：

```text
线性层得到 Q、K、V
    → 对 Q、K 做 RoPE（注入位置）
    → self-attention(Q,K,V)
```

所以：

- **Linear**：学会「内容」投影
- **RoPE**：在注意力打分前，给 Q/K 打上「你在序列何处」
- **Attention**：用带位置信息的 Q/K 去对齐 V

RMSNorm 管的是激活尺度；RoPE 管的是位置几何。二者解决的问题不同。

## 9. 常见踩坑清单

1. **配对方式**：必须是前后半 `[a|b]`，不是相邻交错。
2. **位置来源**：用 `pos_ids`，不要用循环变量 `i` 代替。
3. **$d$ 必须为偶数**：奇数无法干净对半；测试里都是偶数。
4. **每个 head 各自旋转**：`nhead` 维只是并行多份，公式按 head 独立套同一套 $\phi$（$\phi$ 只依赖位置与 $j$，不依赖 head 编号）。
5. **半精度**：`sin` / `cos` 与乘加在 float32 做，最后再写回 F16/BF16。
6. **$\theta$ 的幂**：指数是 `2*j/d`（浮点除法），不要写成整数运算把分数截断成 0。

## 11. 收束：RoPE 到底在干什么？

用三句话收束本讲义：

1. 注意力内积本身不认词序；必须把位置信息注入 Q/K。
2. RoPE 的办法是：把每个 head 向量拆成前半 $a$、后半 $b$，对每个配对 $(a_j, b_j)$ 按角度

$$
\phi_{i,j} = \frac{p_i}{\theta^{2j/d}}
$$

做二维旋转。

3. 本作业要你实现的，就是这个对 `[seqlen, nhead, d]` 连续张量、配合 `pos_ids` 与 `theta` 的逐元素旋转；配对方式与公式以 README 和 `test/ops/rope.py` 为准。

读完这篇，你应当能不看代码口述：输入长什么样、$a$/$b$ 怎么切、$\phi$ 怎么算、为什么 `pos_ids` 可能从 512 开始、输出哪两行公式。然后再动手写 `src/ops/rope/`。
